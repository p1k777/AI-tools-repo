# Contributing Guide

Спасибо за интерес к проекту! В этом документе описаны основные правила внесения изменений.

## 1. Создание ветки

Перед началом работы создайте отдельную ветку от `main`.

Рекомендуемые названия веток:
- `feature/short-description` — новая функциональность
- `fix/short-description` — исправление ошибки
- `docs/short-description` — изменения документации

## 2. Требования к изменениям

- Соблюдайте существующий стиль кода.
- Не добавляйте изменения, не связанные с решаемой задачей.
- Проверяйте работоспособность кода перед отправкой.
- Не включайте в коммиты пароли, API-ключи и другие секретные данные.
- По возможности добавляйте тесты для новой функциональности.

## 3. Создание Pull Request

После завершения работы создайте Pull Request в ветку `main`.

В описании PR укажите:
- Цель изменений.
- Что было добавлено или исправлено.
- Как проверить результат.

Один PR должен решать одну конкретную задачу.

## 4. AI Code Review

В репозитории предусмотрен автоматизированный процесс проверки кода с помощью ИИ.

Для запуска AI-ревью добавьте команду в описание Pull Request:

`/make_ai_review`

Если поддерживается запуск по комментариям, команду можно отправить отдельным комментарием к PR.

ИИ анализирует изменения и может сообщить о:
- Логических ошибках.
- Возможных исключениях.
- Проблемах безопасности.
- Ошибках обработки данных.
- Проблемах производительности.

**Результаты AI-ревью носят рекомендательный характер.** Автор PR должен самостоятельно проверить замечания перед внесением исправлений.

## 5. Issues

Используйте Issues для сообщений об ошибках, предложений новой функциональности и других задач.

При создании Issue:
- Укажите понятный заголовок.
- Подробно опишите проблему или предложение.
- Для ошибок добавьте шаги воспроизведения, ожидаемое и фактическое поведение.

## 6. Merge

Перед слиянием Pull Request убедитесь, что:
- Изменения соответствуют поставленной задаче.
- Код проверен и не содержит известных ошибок.
- Замечания ревью рассмотрены.
- Отсутствуют случайные или посторонние изменения.

После проверки Pull Request может быть объединён с основной веткой.
